Lightroom & duplicate cleanup

Will a duplicate finder break my Lightroom catalog?

Short answer: it can't corrupt your catalog, and it can't lose your edits — but it can make photos go missing until you put them back.

Your develop settings, crops, ratings, keywords and collections live inside the catalog file, not inside the photo. Moving or deleting a photo on disk doesn't touch any of that. What it does is break the catalog's pointer to the file, and Lightroom shows that photo as missing.

Whether that's a scare or a disaster depends entirely on one thing: whether the tool you used can put the file back exactly where it was.

Stated plainly up front: DuplicateFinder Pro does not read your Lightroom catalog. It skips Lightroom's working folders, but it has no idea which photos you've catalogued. What it has instead is a 24-hour quarantine and a restore that puts files back on their exact original path — which is why a mistake here is a one-click fix rather than lost work. What Lightroom actually stores

Almost every worry about duplicate finders and Lightroom comes from one misunderstanding: people assume their editing work lives in the photo. It doesn't.

Lightroom is a non-destructive editor. It never rewrites your RAW file. Every adjustment you have ever made is a database row in the catalog, pointing at a file path on disk.

In the catalog (.lrcat)

  • All develop settings and crops
  • Ratings, flags, colour labels
  • Keywords and metadata
  • Collections and stacks
  • History for every photo
  • The file path each photo points to

On disk

  • The RAW or JPG file itself
  • Nothing else that Lightroom needs

This is why the answer above is what it is. A duplicate finder operates on the right-hand column only. It has no way to alter the left-hand column, because it never opens the catalog file at all.

What actually happens when a catalogued photo is moved

Lightroom keeps preview images of its own, so the first surprise is that nothing looks broken immediately. You'll still see thumbnails. What you get is a small exclamation-mark badge on the affected photos, and a message about the file being offline or missing when you try to develop or export one.

That state is entirely recoverable, and it's recoverable in two different ways:

  • Put the file back where it was. The catalog's stored path becomes valid again and Lightroom reconnects on its own. Nothing to click.
  • Point Lightroom at the file's new location using Find Missing Photo, or Library → Find All Missing Photos for a batch.

The first is far less work, and it's the one that matters when choosing a tool. A duplicate finder that deletes leaves you only the second option — and only if the file went to the Recycle Bin and is still there.

What DuplicateFinder Pro does about this

Two things by design, and one honest gap.

Lightroom's working folders are never scanned

Lightroom's .lrdata preview folders and .cache directories are excluded from scanning outright, alongside Windows, Program Files, the Recycle Bin and Adobe Premiere Pro's working folders. Preview pyramids contain many similar-looking files, which is exactly the kind of thing a duplicate scan should never be turned loose on. You can add your own exclusions on top and save them as reusable profiles.

Nothing is deleted, so putting a file back is one click

Files identified as duplicates are moved to a quarantine folder on the same drive and recorded — not erased. For 24 hours they can be restored with one click, and restore returns each file to its exact original path. Because the path is identical, Lightroom reconnects by itself: no Find Missing Photo, no re-linking, no lost edits. After the hold, files stay in quarantine until you choose to empty it yourself, and restore is never locked behind a licence.

The gap: it doesn't read your catalog

DuplicateFinder Pro has no knowledge of which photos are in your catalog and which aren't. It sees files on disk. If you quarantine a photo Lightroom has catalogued, Lightroom will show it as missing until you restore it — which is a one-click fix rather than lost work, but it is a real inconvenience and worth knowing before you start. Catalog awareness is a planned feature, not a shipped one, and this page will say so until that changes.

How to clean up an archive without the scare

This sequence works with any duplicate finder, not just this one.

  1. Back up the catalog first File → Back Up Catalog, or just copy the .lrcat somewhere safe. It takes seconds and it is the only irreplaceable file in the whole operation.
  2. Scan and read the report before moving anything Scanning and exporting the full CSV and HTML report is free in DuplicateFinder Pro — no licence needed. Read what it found before you act on any of it.
  3. Start with folders your catalog doesn't cover Old camera dumps, card backups, an archive drive you never imported. These are where most duplicates live and where nothing can go missing in Lightroom at all.
  4. Exclude your active catalog folders on the first pass Add them as exclusions and save the set as a profile. You can widen the scope later, once you trust what the tool is reporting.
  5. After quarantining, open Lightroom and look Do this while the 24-hour hold is still running. If photos show as missing, restore and they reconnect on their own. This is what the hold is for.
  6. Empty quarantine only when you're satisfied The space isn't reclaimed until you do — quarantine moves files rather than copying them, so holding them costs nothing while you check.

Related questions

Can a duplicate finder corrupt my Lightroom catalog?

Not by moving or deleting photos. The catalog is a separate database file that a duplicate finder never opens. What can happen is that photos show as missing because their file paths no longer resolve — a broken link, not a corrupted database.

Will I lose my edits if a photo gets deleted?

Your develop settings stay in the catalog regardless. If you restore the file to its original path, the photo reconnects with every adjustment intact. If the file is permanently gone and you have no backup, the settings remain but have nothing to apply to.

Is it safe to delete duplicate RAW and JPG pairs?

That depends on your workflow, not on the tool. If the JPG is an export you can regenerate from the RAW, removing it is low-risk. If you catalogued both and built collections around the JPG, treat it as a catalogued photo like any other and check Lightroom before emptying quarantine.

Should I run a duplicate finder on my Lightroom previews folder?

No. Preview pyramids contain many near-identical images by design, and they're rebuildable working files rather than originals. DuplicateFinder Pro excludes .lrdata and .cache directories automatically for this reason.
